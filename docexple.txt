==============================================================================
GUIDE D'IMPLÉMENTATION : EXEMPLE COMPLET (PERSONNE & CONTACT)
==============================================================================

Ce document retrace toutes les étapes réalisées pour implémenter les entités `Personne` et `Contact` dans le module `ProfilManagement` (Backend).

SCÉNARIO :
- Personne : { id, nom, prenom, age, nationalite, genre, taille, poid }
- Contact : { id, personne_id, telephone, email, adresse }
- Relation : One-to-Many (Une personne a plusieurs contacts).

------------------------------------------------------------------------------
ÉTAPE 1 : CRÉATION DES MODÈLES (apps/profilmanagement/models/)
------------------------------------------------------------------------------
Nous avons créé deux fichiers pour définir la structure de la base de données.

1. `personne.py` :
   - Définit les champs de base (nom, prenom, age, etc.).
   - Utilise `choices` pour le genre (M/F/O).

2. `contact.py` :
   - Définit la clé étrangère vers Personne (`related_name='contacts'`).
   - Définit les champs de contact (email, telephone).

3. Mise à jour de `__init__.py` pour exposer ces modèles.

------------------------------------------------------------------------------
ÉTAPE 2 : CRÉATION DES SERIALIZERS (apps/profilmanagement/api/serializers/)
------------------------------------------------------------------------------
Les serializers transforment les objets BDD en JSON et valident les entrées.

1. `contact_serializer.py` : Serializer standard.
2. `personne_serializer.py` :
   - Inclut `contacts = ContactSerializer(many=True)` pour permettre la création imbriquée (Nested Write).
   - Cela permet d'envoyer un JSON complet : `{ "nom": "Doe", "contacts": [...] }`.

------------------------------------------------------------------------------
ÉTAPE 3 : CRÉATION DES SERVICES (apps/profilmanagement/services/)
------------------------------------------------------------------------------
C'est ici que réside la logique métier, notamment la sauvegarde transactionnelle.

1. `contact_service.py` : Service standard.
2. `personne_service.py` :
   - Surcharge `save_process` pour gérer la sauvegarde des contacts en même temps que la personne.
   - Extrait la liste `contacts` du payload.
   - Sauvegarde la Personne.
   - Crée les Contacts liés à cette Personne.

------------------------------------------------------------------------------
ÉTAPE 4 : CRÉATION DES CONTROLLERS (apps/profilmanagement/api/controllers/)
------------------------------------------------------------------------------
Ils exposent les endpoints REST pour l'écriture (POST/PUT/DELETE).

1. `personne_controller.py` : Connecte `PersonneService` et `PersonneSerializer`.
2. `contact_controller.py` : Connecte `ContactService` et `ContactSerializer`.

Grâce au `RouterController`, les routes sont automatiquement :
- `/api/personne/save/`
- `/api/personne/delete/`
- etc.

------------------------------------------------------------------------------
ÉTAPE 5 : CRÉATION DES TYPES GRAPHQL (apps/profilmanagement/graphql/Types/)
------------------------------------------------------------------------------
Définit le schéma de lecture pour GraphQL.

1. `personne_type.py`
2. `contact_type.py`

------------------------------------------------------------------------------
ÉTAPE 6 : CRÉATION DES QUERIES GRAPHQL (apps/profilmanagement/graphql/Queries/)
------------------------------------------------------------------------------
Définit les points d'entrée de lecture (List, GetById).

1. `personne_query.py` :
   - `resolve_personnes` : Appelle `PersonneService.list()` (avec filtres).
   - `resolve_personne` : Appelle `PersonneService.get_by_id()`.

2. `contact_query.py` : Idem pour les contacts.

------------------------------------------------------------------------------
ÉTAPE 7 : MISE À JOUR DU SEEDER (apps/core/management/commands/seed_navigation.py)
------------------------------------------------------------------------------
Pour que ces nouvelles entités apparaissent dans le menu et soient gérées par le système de permissions.

Action :
- Ajout de deux entrées dans `MODULE_STRUCTURE` (sous "Admin" ou "ProfilManagement") :
  - Page "Personne" (lien `/personnes`, tag `personne`)
  - Page "Contact" (lien `/contacts`, tag `contact`)

------------------------------------------------------------------------------
CONCLUSION
------------------------------------------------------------------------------
L'implémentation est complète côté Backend.
- Les données sont structurées (Models).
- L'API d'écriture est prête et transactionnelle (Services + Controllers).
- L'API de lecture est prête et optimisée (GraphQL + Services).
- L'intégration dans l'application est faite (Seeder).

Prochaine étape : Lancer `python manage.py makemigrations` et `migrate` pour appliquer les changements en base.

------------------------------------------------------------------------------
PARTIE 2 : IMPLÉMENTATION FRONTEND (Angular + GraphQL)
------------------------------------------------------------------------------
L'implémentation frontend suit une architecture stricte pour garantir la cohérence avec le module `User`.

1. DÉFINITION GRAPHQL (frontend/src/app/features/profilmanagement/graphql/profil.graphql)
   - On définit les requêtes GraphQL pour `Personne` et `Contact`.
   - IMPORTANT : Consolidé dans un seul fichier pour simplifier la génération.
   - Les requêtes doivent inclure la pagination (`items`, `totalCount`, `numPages`, `currentPage`) pour correspondre aux attentes du composant générique `UiListPage`.
   - Les formulaires imbriqués (ex: Personne + Contacts) nécessitent de récupérer les relations (`contacts { ... }`) dans le `GetById`.

2. GÉNÉRATION DES TYPES (CODEGEN)
   - Commande : `npm run codegen`
   - Génère les services typés dans `src/app/graphql/generated.ts`.
   - ATTENTION (Point Critique) : L'introspection GraphQL nécessite d'être authentifié.
     - Solution temporaire : Désactiver temporairement `IsAuthenticated` dans `apps/core/api/controllers/GraphQlController.py` le temps du codegen.
     - Solution durable : Passer le token JWT dans la config codegen (plus complexe).

3. SERVICE (frontend/src/app/features/profilmanagement/services/)
   - `personne.service.ts` : Étend `BaseService`.
   - Injecte `GetAllPersonnesGQL` généré par codegen.
   - Fournit la méthode `getQuery()` pour le `BaseListComponent`, qui attend un `DocumentNode` GraphQL pour faire la requête elle-même (pattern Apollo WatchQuery).

4. COMPOSANT FORMULAIRE (PersonneFormComponent)
   - Étend `BaseFormComponent` (gestion du loading, submit standard).
   - Utilise `@Input() personne` et `ngOnChanges` pour gérer le mode édition.
   - Utilise `UiTabsComponent` pour séparer "Infos Générales" et "Contacts".
   - Utilise `FormArray` pour gérer la liste dynamique des contacts (Ajout/Suppression).
   - La méthode `save()` construit le payload et appelle `PersonneService.save()`.

5. COMPOSANT LISTE (PersonneListComponent)
   - Étend `BaseModalListComponent<Personne>`.
   - Définit les colonnes du tableau (`tableColumns`).
   - Utilise le pattern de projection de contenu (`ng-content`) pour s'intégrer dans `UiListPageComponent` (toolbar, filters, table, pagination, modals).
   - Utilise `app-personne-form` à l'intérieur de sa modale de création/édition.

6. ROUTING DYNAMIQUE (LE PIÈGE À ÉVITER ⚠️)
   - C'est le point le plus crucial et la source fréquente d'erreurs "silencieuses" (clic sans effet).
   - Le menu est généré dynamiquement via `seed_navigation.py` (Base de données).
   - Le Router Angular (`DynamicRouterService`) intercepte la navigation.
   - IL FAUT IMPÉRATIVEMENT ENREGISTRER LE COMPOSANT DANS LE REGISTRE.

   Fichier : `frontend/src/app/core/routing/component.registry.ts`
   
   ```typescript
   export const COMPONENT_REGISTRY: Record<string, () => Promise<any>> = {
       // ...
       '/personnes': () => import('../../features/profilmanagement/components/personne-list/personne-list.component').then(m => m.PersonneListComponent),
   };
   ```
   
   Sans cette ligne, l'application connaît l'URL mais ne sait pas quel fichier charger.
